## What

Pulls the transaction-log API (rows from a log table, `serviceId` / `from` / `to`, `api-key` header) into the stack and adds a **💳 Wall — Transactions** board (`/d/wall-transactions`).

## How

- **`txn-poller`** (`transactions/txn_poller.py`, stock `python` image running the mounted script, standard library only) calls the API once per `TXN_POLL_INTERVAL` (60 s) and writes:
  - **Prometheus** (`:9488/metrics`): `txn_transactions_total` / `txn_operations_total` by service, service type, channel, provider and result, plus provider and Coure response-time histograms and feed-health metrics.
  - **Loki**: one JSON record per transaction (phone number masked to its last 4 digits), with timestamps taken from `transactionTimeStamp`.
- **Grafana never calls the API.** The time picker (`$__range`) and the Service / Channel / Provider dropdowns run against Prometheus and Loki, so the API load stays the same however many screens show the wall.
- **No gaps and no double counting:** each poll re-reads `TXN_OVERLAP` (120 s) to pick up rows written late, and skips any `transactionRef` it has already counted. The poller keeps a watermark per service and the refs it has seen recently in a volume, so a restart picks up where it stopped (catch-up capped by `TXN_MAX_BACKFILL`).
- **Keeping label counts low:** client, phone and ref stay out of the metric labels and go to Loki only. Each label is capped at `TXN_MAX_LABEL_VALUES`, and values past the cap are grouped as `other`.
- **Paging:** set `TXN_PAGE_PARAM` / `TXN_PAGE_SIZE_PARAM` to read every page. While they're unset, the poller warns and counts `txn_pages_skipped_total`.
- It only runs if you opt in: add `transactions` to `COMPOSE_PROFILES`. The scrape target is generated by `scripts/render-transactions-config.sh` and stays empty while the profile is off, so a site without the feed gets no false "down" alerts.
- **Alerts:** `TxnFeedFailing`, `TxnFeedUnauthorized`, `TxnLowSuccessRate` (< 95 % over 15 min, needs at least 20 transactions), `TxnProviderSlow` (p95 > 5 s).
- Smoke test check, links to the new wall from every wall and from the NOC Overview, guide section 2.12, reference and UPGRADING notes.

## Testing

- Mock API (paged, requires a key) + fake Loki: across a poller restart, 102 transactions were counted in Prometheus and 102 records were pushed to Loki, with no duplicates and no gaps in the refs. A wrong key gives `txn_poll_errors_total{reason="http_401"}` and `txn_poll_success 0`.
- Real Prometheus v3.1.0 + Loki 3.3.0 fed by the poller: all 4 wall variables and all 12 panel queries return data.
- `promtool check rules` (20 rules) and `check config` pass. `bash -n` passes on the changed scripts, and `check-targets.sh` accepts the generated target file.
- **Not yet tested against the real API.** These are assumptions to confirm: response times are in ms, the page parameter name, and whether `serviceId=""` returns every service.
